05 · Video podcast production · Windows desktop

Personal build · v0.12

RosalindCam Studio

A live-production app for video podcasts. I built it to produce my own show: one app instead of five, with on-device post-production and no subscription.

Stack C#.NET 8WPFWebRTC (WebView2)FFmpegNAudioOpenCvSharpONNX Runtime (DirectML)whisper.cppllama.cpp

Why I built it

I have more time than money, so it's more cost-efficient to build my own apps than pay someone else to use theirs.

  • To produce my own show
  • One app instead of five
  • No subscription costs

Live production

  • Separate Preview and Program with a deliberate TAKE; scenes, run of show, preflight checks, autosave and recovery
  • Four-channel mixer (mic, media, system, master) with mix-minus
  • Records up to 4K, MKV first and remuxed to MP4, with seven separate stereo tracks
  • Streams to YouTube (1080p30 RTMPS) with an automatic safety recording and bounded reconnects
  • YouTube chat panel with a Q&A queue and on-screen comment cards; lower-thirds and ticker graphics
  • Up to three remote guests over WebRTC, with a green room and private join links

On-device post-production

No cloud, no per-use fees

  • Dialogue isolation and a transcript editor (Whisper)
  • An episode producer that drafts titles, descriptions, chapters, and show notes with inspectable citations (local LLM via llama.cpp)
  • Clip drafts with 9:16 framing and captions, and thumbnail concepts from a local image model

I review everything before export.

Engineering

837 automated checks

In the full Studio suite. It shares a Core library with RosalindCam and has a 22-page printable user guide.

Honest status: a personal build. Real-device acceptance of the guest features is still in progress.

06 · Screen & webcam recorder · Windows desktop

Personal build

RosalindCam

A focused recorder for talking-head and screen videos. It records the screen, the webcam, or both with microphone audio to 1080p MP4, and ships as a portable, self-contained .exe.

Stack C#.NET 8WPFOpenCvSharpONNX Runtime (DirectML)NAudio (WASAPI)FFmpeg

Why I built it

OBS was confusing for me to use. I tried to like it, but I couldn't.

  • A focused recorder for talking-head and screen videos
  • Hide my room on camera without a green screen
  • No subscription, watermark, account, or cloud

Background replacement

No green screen needed

Real-time colour, image, or blur backgrounds using the RobustVideoMatting model on the GPU (ONNX Runtime + DirectML, CPU fallback), with edge controls.

Recording modes

  • Screen only
  • Webcam only
  • Screen + webcam
  • Picture-in-picture
  • Side-by-side

The picture-in-picture webcam is movable and resizable, even while recording.

Crash-safe recording

  • Writes MKV first, then remuxes to MP4
  • AMD hardware H.264 with a software fallback
  • 99-check native smoke suite

How I work

Six habits that show up across these projects.

1

Start from the problem, not the ticket

Each product started from a specific audience: homeschool co-ops and learning centers, small import/export operators, founder-led SaaS companies, website owners, and, for the desktop apps, me.

2

Own the whole stack

Product decisions, UX, data model, back end, front end, payments, deployment, and hardening. One person accountable for all of it.

3

AI is a tool; accountability is mine

I use AI to move faster. Architecture, code review, verification, security, and the final call are still my job.

4

Verify live, not just on paper

Scholium got a dedicated security phase with live tests of session rotation, login lockout, CSRF rejection, and auth flows. The Decision Suite runs 49 validation checks; RosalindCam Studio's suite runs 837.

5

Right-size the solution

I removed Scholium's planned Xero and QuickBooks integrations (13 files, 4 tables) and shipped five CSV exports that work with any accounting tool.

6

Build the tool I need

I have more time than money, so building my own apps is more cost-efficient than paying to use someone else's. RosalindCam and RosalindCam Studio came from that.
