Qorva Global Trade

A workflow platform for solo and small import/export operators.

Qorva highlight reel1080p · about a minute

covers

  • Landed-cost planning from FOB to DDP
  • Duty estimates, including Section 301/232
  • HS-code reference and search
  • Shipment tracking and purchase orders
  • Document workflows and reconciliation
  • Reporting and accounting-oriented exports
  • Live FX rates via frankfurter.app

plans · flat pricing

Standardmonthly · yearly
Promonthly · yearly

stack

  • Laravel
  • PHP
  • REST integrations
  • frankfurter.app FX
  • HTS data pipeline

decisions

  1. pipeline

    Tariff data that follows each HTS revision

    The pipeline fetches each new revision of the U.S. Harmonized Tariff Schedule, diffs it against the prior revision, and updates base rates, Chapter 99 additional duties, and preference-program data accordingly.

    fetch→ diff vs. prior→ update rates

  2. duties

    Section 301 and 232 in the estimate, not as a footnote

    Duty estimates include the additional Section 301/232 duties, so landed-cost plans reflect what an operator would actually owe.

  3. integration

    Live FX from frankfurter.app

    Exchange rates come from a REST integration rather than manual entry.

REC-03/decision-suite/Financial decision system · web Offline

Financial decision system · web

SaaS Financial Decision Suite

The flagship demonstration for my planned fixed-scope consulting practice at rosalindgash.com: financial decision systems for founder-led SaaS companies.

note: Havenpoint Workflow is a fictional SaaS company. All 24 months of its data are synthetic.

four modules · one dataset

  • Performance & Cash
  • Accounting & Assets
  • Workforce & Hiring
  • Tax Readiness & Expansion
  • Executive overview (Founder Decision Center)
  • SaaS Financial Visibility Scorecard

scenario controls

  • Churn
  • New-customer pricing
  • New-business strength
  • A hire
  • UK market entry

Each one flows through the 12-month forecast where it is financially relevant: a hire changes burn and runway; churn moves ending MRR and cash.

stack

  • Next.js 16
  • React 19
  • TypeScript (strict)
  • Tailwind CSS
  • Recharts

decisions

  1. verification

    49 automated validation checks

    The checks cover a 24-month MRR bridge, cash reconciliation, assets = liabilities + equity, NPV/IRR recomputation, the book-to-tax bridge, and scenario propagation.

    49 checksMRR · cash · A = L + E · NPV/IRR · tax

  2. architecture

    Formulas live in one calculation library

    Nothing is computed inside components. A metric dictionary and an assumptions register document what every number means and where it comes from.

  3. accessibility

    Charts with data-table alternatives

    Every chart has a table view as part of WCAG 2.1 AA work. The contact form fails closed, using a server action and a honeypot.

status:Offline for now, along with rosalindgash.com. Paired with REC-04.

REC-05/rosalindcam-studio/Video podcast production · Windows Personal build · v0.12

Video podcast production · Windows

RosalindCam Studio

A live-production app for video podcasts, with post-production that runs on my own machine.

live production

  • Separate Preview and Program with a deliberate TAKE
  • Scenes, run of show, preflight checks, autosave and recovery
  • Four-channel mixer (mic, media, system, master) with mix-minus
  • Records up to 4K with seven separate stereo tracks, MKV first, remuxed to MP4
  • Streams to YouTube at 1080p30 over RTMPS, with an automatic safety recording and bounded reconnects
  • YouTube chat panel with a Q&A queue and on-screen comment cards; lower-thirds and ticker graphics
  • Up to three remote guests over WebRTC, with a green room and private join links

post-production · on-device

  • Dialogue isolation
  • Transcript editor using Whisper
  • Episode producer that drafts titles, descriptions, chapters, and show notes with inspectable citations (local LLM via llama.cpp)
  • Clip drafts with 9:16 framing and captions
  • Thumbnail concepts from a local image model
  • I review everything before export.

why i built it

I wanted to produce my own show with one app instead of five, and without subscription costs.

“I have more time than money, so it's more cost-efficient to build my own apps than pay someone else to use theirs.”

stack

  • C#
  • .NET 8
  • WPF
  • WebRTC (WebView2)
  • FFmpeg
  • NAudio
  • OpenCvSharp
  • ONNX Runtime (DirectML)
  • whisper.cpp
  • llama.cpp

decisions

  1. on-device

    Post-production with no cloud and no per-use fees

    Transcription, drafting, clips, and thumbnails run on local models. Nothing leaves the machine, and nothing is exported without my review.

  2. safety

    Preview, Program, and a deliberate TAKE

    Changes are prepared in Preview and reach Program only on a TAKE. Streams keep an automatic safety recording and reconnect within set limits.

  3. verification

    A shared Core and 837 automated checks

    Studio shares a Core library with RosalindCam. The full Studio suite runs 837 automated checks, and the app ships with a 22-page printable user guide.

    837 checks22-page guide

status:Personal build, v0.12. Real-device acceptance of the guest features is still in progress.

REC-06/rosalindcam/Screen & webcam recorder · Windows Personal build

Screen & webcam recorder · Windows

RosalindCam

A focused recorder for talking-head and screen videos.

why i built it

I wanted a focused recorder for talking-head and screen videos. OBS was confusing for me to use: “I tried to like it, but I couldn't.” I also wanted to hide my room on camera without a green screen, with no subscription, watermark, account, or cloud.

records

  • Screen, webcam, or both, with microphone audio to 1080p MP4
  • Picture-in-picture you can move and resize while recording, or side-by-side
  • Background replacement or blur in real time, with edge controls
  • Portable, self-contained .exe

stack

  • C#
  • .NET 8
  • WPF
  • OpenCvSharp
  • ONNX Runtime (DirectML)
  • NAudio (WASAPI)
  • FFmpeg

decisions

  1. ml

    No green screen required

    Background replacement (colour or image) and blur use the RobustVideoMatting model on the GPU through ONNX Runtime and DirectML, with a CPU fallback.

  2. reliability

    Crash-safe recording

    Recordings are written to MKV first, then remuxed to MP4. Encoding uses AMD hardware H.264 with a software fallback.

    MKV→ MP4

  3. verification

    A 99-check native smoke suite

    The portable build is checked by a native smoke suite of 99 checks.

status:Personal build. Shares its Core library with RosalindCam Studio.

03how i work

Working principles

  1. 01

    Start from the problem, not the ticket

    Every product here began with the people it serves: co-op administrators, small importers, SaaS founders, site owners, and sometimes me. The features follow from their work.

  2. 02

    Own the whole stack

    Product decisions, UX, architecture, payments, deployment, and hardening are one job. I don't hand off the parts that are hard to get right.

  3. 03

    AI is a tool; accountability is mine

    I use AI as an engineering tool. I delegate architecture and implementation, but responsibility for requirements, review, verification, security, and final product decisions stays with me.

  4. 04

    Verify live, not just on paper

    Static review is a start. Scholium's security phase was tested against the running app; the Decision Suite runs 49 validation checks and Studio runs 837.

  5. 05

    Right-size the solution

    Five CSV export types replaced the planned Xero and QuickBooks integrations: 13 fewer files, 4 fewer tables, and compatibility with any accounting tool.

  6. 06

    Build the tool I need

    I have more time than money. When a subscription tool doesn't fit how I work, I build my own, as I did with RosalindCam and RosalindCam Studio.
